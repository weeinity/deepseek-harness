# Agent Note: 个人助理回执与提问

Status: implemented

[English](2026-09-18-personal-assistant-receipts-and-questions.md) | 中文

## Problem

个人助理需要区分收到请求、同意、获得权限和完成操作。乐观输入回显与排队任务不能证明处理准入。用户角色消息也可能包含委派任务或注入上下文，因此仅凭角色不能识别直接人类输入。

## Decision

以下自动准入回执策略已由[助理选择的表情回应](2026-09-19-personal-assistant-selective-reactions.zh.md)取代。本记录仍适用于共享标记槽位、直接输入来源、作用域问题和独立写入审批。

共享 Chat 在已准入的用户消息和引导消息旁拥有一个可叠加、默认空置的 `conversation.chat.user-badges` 槽位。其拥有者提供规范消息身份和经过验证的 Web 提示请求来源，而不是消息文字。[助理 UI](../../../../work-assistant/packages/wa-ui/README.zh.md) 仅在 Session 已解析的预设匹配明确的展示策略且存在该来源时，贡献非交互式回执。

徽标表示收到，不表示理解、授权或成功。竖拇指、中性文字和关闭由部署选择；Client 不会在模型读取请求之前判断情绪。历史从已准入记录重建相同展示，不需要回执事件、模型调用、确认存储或回放播报。后续失败不撤销准入事实。

[个人助理预设](../../../../work-assistant/packages/wa-preset/README.zh.md) 拥有主动、简洁的指导，并在其 Agent 作用域中挂载现有人类提问工具。[网关](../../../../work-assistant/packages/wa-gateway/README.zh.md) 准入精确的交互定义，而不是任何同名工具。问题答案不能提供连接器写入授权。连接器参数被捕获以供审计和分发，而该实时 Agent 中的新直接人类输入会使待定写入审阅失效。

可用日历连接器是只读的。助理可以检查其配置的日历并起草邀请文字，但没有目录查询、其他参与者忙闲服务、邀请发送器、提醒写入器或提供方结果核对。不添加推测性的日历适配器或操作账本。记忆写入保留每次新的一次性审批、预期修订和独占写入锁。

## Alternatives considered

**仅靠提示词的表情或确认工具。** 提示文字不能装饰现有用户气泡。工具或单独模型回复增加请求或会话输出，却不能确立更早的准入事实。

**在提交、入队或 Agent 空闲时显示回执。** 这些状态分别发生在准入之前，或描述一段区间而不是具体输入。它们都不能证明精确的用户消息已进入处理。

**为所有用户角色行显示回执。** 委派和注入上下文也可能使用该角色。要求可信 Web 入口来源，明确排除了不受支持的旧来源和非 Web 来源。

**替换私有消息渲染器或修改其 DOM。** 这些方式会接管附件、复制控件、滚动和其他无关展示。可叠加槽位保留共享渲染器的归属与默认行为。

**把问题答案当作审批，或在没有提供方时添加会议框架。** 现有审批服务拥有写入授权。日历来源不能发送邀请；虚构执行器会误述能力，并引入无法测试的恢复承诺。

## Consequences

回执需要共享 Chat 扩展；未打补丁的已发布运行时无法显示它。关闭贡献会保留现有展示。禁用回执也会隐藏历史徽标，而不删除或改写 Session 记录。

预设更新影响新装配的 Agent，而不是已运行 Agent 的指令。禁用指导或回执不会撤销已完成的记忆写入。现有审计和 Git 记录仍然可用；不确定结果不会被自动重放。

网关和交互测试覆盖精确工具准入、取消和审批分离。当前展示覆盖由选择性表情回应决策拥有。确定性夹具不能证明真实日历提供方行为或部署模型的遵循率。

[右侧面板决策](../architecture/2026-09-17-personal-assistant-right-panel.zh.md)、[操作准入决策](../architecture/2026-09-17-personal-assistant-action-admission.zh.md)和[规范反馈决策](../architecture/2026-09-05-canonical-feedback-log.zh.md)保持有效。回执既不是另一个活动数据库，也不是用户对助理回复的反馈。
