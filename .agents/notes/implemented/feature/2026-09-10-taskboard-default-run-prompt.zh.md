# Agent Note: Taskboard 默认运行提示词

Status: implemented

[English](2026-09-10-taskboard-default-run-prompt.md) | 中文

## 问题

任务标题标识工作，而描述可能包含执行工作所需的指令。只提交标题会遗漏这些指令，除非用户将其复制到独立的运行提示词中。

## 决策

运行提示词为空时，使用以空行分隔的标题和非空白描述。非空白运行提示词覆盖两者并原样保留。仅含空白的描述不贡献内容；非空白描述保留其格式。

本决策仅取代[Taskboard 执行与互斥对话](2026-09-09-taskboard-execution-and-conversations.zh.md)中只使用标题的默认规则。其执行所有权、恢复和对话决策仍然有效。

领域在持久化准入时解析一次输入，供 DSH、Copilot、手动运行和定时运行共同使用。冻结的交接信息随后追加。再次运行使用当前已保存字段；尚未结束或历史执行及匹配请求的重放保留原始输入。Version-1 迁移保留已形成的明确提示词，不重写 Session 日志。

## 考虑过的替代方案

**仅将描述作为计划文本。**这要求将执行指令复制到另一个字段，并使任务仅以简短标题作为模型输入。

**始终将描述追加到明确填写的提示词。**这会取消用户的覆盖选择，并可能提交无关或冲突的计划文本。

## 测试

领域回归测试固定空白处理、精确覆盖、交接、定时准入、冻结执行尝试和编辑后同一对话的再次运行。Host 回归测试检查向两种提供方的派发。[Web 录制场景](../../../../snapshots/web/taskboard-start-work/)通过持久化用户消息检查默认值和明确覆盖，同时保留借用的真实录制。

## 影响

运行提示词为空的任务会提交描述，并消耗相应的输入 token。需要独立执行指令的用户可以填写运行提示词。任务编辑不会改变已接受的工作。
