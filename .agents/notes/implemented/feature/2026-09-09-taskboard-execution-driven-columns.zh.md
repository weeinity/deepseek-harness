# Agent Note: Taskboard 执行驱动的列状态

Status: implemented

[English](2026-09-09-taskboard-execution-driven-columns.md) | 中文

## Problem

任务所在列必须显示执行正在工作、需要用户输入还是已经结束。Run 或完成后还要单独手动移动，会使看板过时。

## Decision

本说明取代[原生 Taskboard](2026-09-01-native-workspace-taskboard.zh.md) 与[执行及唯一对话](2026-09-09-taskboard-execution-and-conversations.zh.md) 中仅手动维护状态的决策。这两份说明保留展示、Workspace、持久回执与对话所有权的设计理由。[手动状态控制](2026-09-25-taskboard-manual-status-control.zh.md)只取代本说明中 Todo 的手动移动限制；本说明继续负责执行与用户处理需求触发的自动更新。

创建时省略状态，默认为 Todo。明确的创建选择、副本和已有记录保留其提供的状态。不迁移历史状态。

domain 在持久写入执行准入或观察结果时，一并更新所在列。接受手动或计划运行后进入 In Progress。等待用户输入时进入 In Review，但不结算执行；恢复工作后回到 In Progress。精确确认成功完成后进入 Done。失败和取消的执行进入 In Review。

执行历史与任务所在列仍分别保存。Done 表示执行成功，不代表独立人工审查，也不证明任务的每项要求均已满足。通用对话 idle 状态不是完成证据。回执关联和不重发的恢复仍由执行决策约束。

具有关联证据的待定动态包审批会延后发布原始轮次的成功，直到该请求得到答复。后续 system-steering 轮次不取得原始执行的回执。确定归属需要当前挂载 adapter 的实时请求证据；仅凭 registry 本地标识和 Session 历史，无法在 adapter 重新加载后重建等待。

即使没有未结束的 Taskboard 尝试，用户处理需求仍属于当前关联的 DSH 对话。类型化问题或审批捕获其实时 Agent 和确切轮次。任务进入 In Review，回答后恢复到 In Progress，并跟随该轮次成功或失败的结束结果，不创建执行记录。未关联的 Chat 和已归档任务被排除。后续轮次不能替换已捕获结果；新的待定问题可以建立自己的监控。

断开关联、归档、删除和接纳新执行时，宿主使这些借用的监控失效。修订与关联检查拒绝过期列写入。断开后重连的失效处理观察已提交的任务变化，而不是仅比较最终关联 ID，因此重新关联同一 Session 不会让旧回调重新获得权限。写入失败时保留监控以便重试；所有权丢失会阻止写入，但不取消或回答借用的工作。

每个活动任务均可手动移至任一其他状态，同列重新排序仍有效。domain 根据共享状态顺序派生 `TaskboardTask.allowedManualStatuses`，因此 Client 不维护另一份状态转换表。执行尚未结束时，宿主活动观察可能再次移动人工调整过的卡片。

自动换列会将卡片追加到目标列末尾。活动观察未改变时，不修改修订号、时间戳或排序。重放准入和重复终态确认不会撤销后续手动编辑。结算不要求 Workspace 发现或 provider 可用。

## Alternatives considered

**全部列状态仍由人工控制。** 这保留严格审查步骤，但会使已接受和已完成执行在看板上过时。要求的流程由执行与用户处理需求的观察结果负责更新列。

**所有终态执行都移到 Done。** 失败和取消需要用户处理，必须与成功区分。

**限制手动状态转换。** 这会让执行准入成为 Todo 进入活动列或完成列的唯一方式，但会阻止明确的规划修正。[手动状态控制](2026-09-25-taskboard-manual-status-control.zh.md)在保留独立执行历史的同时允许这些修正。

**把等待输入视为终态失败。** 受支持的问题或审批可以恢复同一次执行。未结束的等待观察保留这种连续性；不受支持的 provider 交互仍明确失败。

**只观察 Taskboard 执行回执。** 关联 Chat 可以在首次 Run 前或后续手动继续对话时提问。复用旧回执会破坏归属；独立的只读提问轮次监控提供用户处理需求，不虚构执行尝试。

## Testing

domain 测试覆盖默认创建、明确状态保留、手动目标投影、原子状态与排序更改、重复观察、请求重放，以及 Workspace 移除后的结算。协调器测试覆盖 In Progress、等待时 In Review、恢复后 In Progress 和 Done，且不重发输入，并覆盖失败和取消恢复。Client 与组装浏览器测试覆盖目标列控件和执行驱动的卡片位置。

关联 Chat 的回归测试覆盖空历史与已结束历史、重叠问题和审批、确切轮次完成、持久化失败、所有权丢失以及任务变更竞态。发布配置的浏览器场景使用真实录制的模型流和实际问题答复器，观察 In Review 卡片并通过 Chat UI 回答；未关联 Chat 的对照验证监控既不创建任务，也不关联对话。

## Consequences

无需浏览器连接，看板即可反映宿主观察到的工作。In Review 同时表示等待用户输入、失败或取消；执行记录解释 Taskboard 运行，关联 Chat 则拥有手动轮次详情。宿主必须保持可用才能观察变化；列更新可能比 provider 实际状态滞后至下一次观察。
