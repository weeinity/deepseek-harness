# Agent Note: 由配置方案持有的 MCP 连接器控制

Status: implemented

[English](2026-09-13-profile-owned-mcp-connector-controls.md) | 中文

## Problem

浏览器开关必须在重启后保留状态，同时不能更改其他插件或覆盖无关的配置方案内容。仅凭 Loader 条目无法确定其可写来源：组合包默认值、配置方案编辑、home 覆盖、调用期覆盖以及嵌套组合都可能共同形成同一棵可见树。活跃的 MCP 插件也不能证明传输已经连接。

## Decision

连接器设置页面按配置中的顺序列出已配置的全局 MCP 条目，包括已禁用条目。启用状态变化时，条目在同一个列表中保留原有元素和位置。页面只投影允许公开的名称、标识符、传输类型和 Loader 阶段；命令、参数、端点、请求头、环境值以及可执行配置表达式都不属于浏览器元数据。

客户端将名称映射到本地打包的身份图标；未知名称使用首字母。标志像素随客户端 bundle 分发；配置方案数据不能指定图片 URL。图标颜色不表示启用状态或传输健康。只读控件显示锁图标，但不淡化身份图标；写入期间禁用控件并不暗示配置限制。

配置方案启动所有者提供写入能力。它将完整的 Loader 标识映射到支持的配置方案本地目标，并只在配置方案补丁中持久保存该目标的 `disabled` 覆盖。未知或不支持的目标、更高优先级覆盖、并非仅监听回环地址的 Web 部署以及缺少该所有者的环境都不能修改配置。不会仅为显示条目而执行已禁用配置。

写入携带最近一次目录读取的修订号，在所有者内串行执行，并拒绝已观察到的过期配置。理解 YAML 的编辑保留无关条目和可信的 `!!js` 表达式。持久化与 Loader 应用具有独立结果：已保存的更改可能需要重启，此类回执不会被报告为激活成功。浏览器采用返回的快照，不提前显示乐观开关状态。

此实现保留[配置方案组合顺序](../architecture/2026-08-05-profile-plugin-bundles.zh.md)以及 [MCP 客户端的配置标识和工具生命周期](2026-07-07-mcp-client-plugin.zh.md)。它增加的是启用状态控制，而不是第二份服务器注册表或安装服务器的 API。

## Alternatives considered

**调用 `loader.update()`，并把完成视为已持久保存。** 根写入可能不执行任何操作，延迟写入错误也不能构成已等待的持久确认。Loader 操作成功不足以证明重启后会使用请求的值。

**写入组合后的 Loader 树。** 将树展平会丢失来源所有权，并可能持久保存已求值的配置。编辑所拥有的配置方案补丁能保留组合关系，并使私有连接数据远离浏览器命令。

**在用户设置中存储第二份连接器目录。** 启动已经读取配置方案组合。独立的启用状态存储需要协调，并可能与显式配置不一致。

**将活跃插件标为“已连接”。** MCP 监督器可能正在重连，或保留非致命启动失败，而其 Loader fiber 仍处于活跃状态。这里可观察的是启用状态与 Loader 阶段；传输健康仍是独立问题。

**使用传输类型作为连接器图标。** 共享同一传输类型的服务器在视觉上无法区分。身份图标无需增加连接数据或远程图片请求即可区分它们；传输类型仍以明确文本呈现。

## Consequences

页面为可写的已配置目标提供持久控制，同时说明其他条目只读的原因。更高优先级配置保持权威，不会被较低优先级编辑器悄悄更改。

配置方案所有者承担持久化复杂性；浏览器不持有连接秘密或配置序列化器。工具可用性通过既有 MCP 生命周期变化，设置页面不发送模型请求。

针对性覆盖包含真实 Loader 组合与 MCP 工具注册、过期及并发写入、配置保留、应用失败和所有者释放。浏览器组件覆盖包含筛选、本地化拒绝消息、待完成写入、过期响应、稳定的条目顺序以及切换后的键盘焦点。
