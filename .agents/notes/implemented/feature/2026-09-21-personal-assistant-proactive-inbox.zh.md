# Agent Note: 个人助理主动收件箱

Status: implemented

[English](2026-09-21-personal-assistant-proactive-inbox.md) | 中文

## 问题

定时助理可以生成保存的对话，却没有让用户看到。临时完成标记在重新连接后消失，而为了恢复可见性重新运行模型会浪费工作，也可能违背用户的暂停操作。仅空闲不能证明简报成功。

## 决策

现有[简报 bundle](../../../../work-assistant/packages/wa-briefing/README.zh.md)拥有其 Cron 定时器、有界只读 Agent、中断策略和持久收件箱。它在 profile 的现有存储后端上使用独立带版本的域，不建立第二个数据库或调度器。计划仍须部署明确启用。[动作准入决策](../architecture/2026-09-17-personal-assistant-action-admission.zh.md)继续约束工具和写入。

一个原子状态记录保存暂停标记、最近尝试的 UTC 分钟、待处理 Session 引用及有界项目列表。创建 Agent 前先记录发生时刻。发布需要完整助理输出和成功的日历证据，Session 刷新先于收件箱写入。重启时只检查待处理 Session：经验证的完整回复只发布一次，不调用模型；不存在或未完成的工作不重试。持久化读取失败会显式呈现，不丢弃引用。

暂停立即终止所拥有的创建或生成，持久化策略，移除竞态中的活动发布，并等待工作静止。后续准入和发布重新核对保存的策略。策略写入失败时，从持久状态恢复最新调用者的有效标记，但仍等待取消的工作结束。恢复只影响未来触发。按数量保留只淘汰预览，不淘汰 Session 日志或发生时刻水位。

[助理界面](../../../../work-assistant/packages/wa-ui/README.zh.md)通过自己的 observable 读取有界同源端点。轮询、重新连接和刷新只获取现有状态，不启动 Agent。侧边栏未读标记在面板收起后仍可见，面板标题预览最新未读回复但不抢占焦点。明确的打开并回复会标为已读并打开普通对话，不自动发送消息。已读和忽略状态独立于[对话表情回应策略](2026-09-19-personal-assistant-selective-reactions.zh.md)。

端点只接受带自定义请求头的环回请求和同源 JSON 修改。它不暴露立即运行动作，也不接受模型选择的目标。无人值守 Agent 保留插件来源和精确的只读工具，不能调用交互问题或写入。软件包更新使用不可变摘要命名归档及明确的 setup 更新选项，保留 profile 补丁、preset 资产和保存的策略。

## 考虑过的替代方案

**仅提示词指令或改写核心循环。** 提示词无法唤醒空闲 Agent。已发布 Agent 的 follow-up API 已提供唤醒，因此由应用决定何时以及为何使用。

**通用持久任务队列或另一个调度器。** 一个已配置简报只需要一个待处理引用和有界收件箱。通用重试、分布式租约和补跑计划增加了不支持的行为；错过和未完成的发生时刻仍跳过。

**临时提示或重新连接时重跑。** 两者都不能可靠保存未读消息。读取持久收件箱将沟通状态与模型执行分离。

**把空闲、表情或问题答案当作成功或权限。** 这些事实不能证明有日历依据的完整回复或写入授权。现有动作审批保持独立。

## 影响

部署支持每个专用 home 一个进程及环回 HTTP，不支持远程或代理来源。崩溃可能在可用回复产生前消耗发生时刻；不承诺 exactly-once 执行。Session 持久化损坏会使恢复失败，不会静默重新生成内容。浏览器推送、外部发送、安静时段、日历变更传感器和约定跟进暂缓；Cron 控制首个里程碑的本地节奏。

[右侧面板决策](../architecture/2026-09-17-personal-assistant-right-panel.zh.md)继续适用于布局和已记录日历及记忆视图。本决策添加独立持久沟通状态，不把那些视图变成活动或任务数据库。动作准入和回执及问题记录保留独立安全与来源依据；没有完全被取代的记录。

## 验证

针对性服务和界面测试负责发生时刻去重、实际完成、未读保留、无模型调用恢复、暂停竞态与失败、HTTP 校验、请求截止时间和用户操作。已安装 profile 覆盖必须使用专用合成 home，并保留普通聊天和表情回应回归。夹具证明确定性行为，不证明真实模型实用性或宿主停止时的送达。
