# Agent Note: Taskboard 执行与唯一对话

Status: implemented

[English](2026-09-09-taskboard-execution-and-conversations.md) | 中文

## Problem

已保存任务的生命周期长于单次智能体执行。创建 Session 或打开终端不能证明智能体已接受任务、完成任务，或产生了经过审查的结果。浏览器拥有的编排也无法在断开后可靠监控工作，或判断中断的提交是否可以安全重复。

具有独立 DSH 和 Copilot 关联的任务无法为 Run Again 提供明确目标。每次运行都更换对话会丢失有用上下文；自动重建缺失对话可能重复工作，并掩盖历史丢失。

## Decision

[原生 Taskboard 展示决策](2026-09-01-native-workspace-taskboard.zh.md) 继续负责布局和 Workspace 归属。本说明取代其中的独立关联与终端拥有启动决策，负责执行和对话策略。[执行驱动的列状态](2026-09-09-taskboard-execution-driven-columns.zh.md) 取代本说明中仅手动维护状态的策略；其他所有权与恢复决策仍有效。

每个任务只有一个当前 DSH 或 Copilot 对话。Run Again 持续使用它，直到明确断开关联。历史执行保留各自标识。已有双关联记录保留两个选项，并阻止执行，直到用户选择其中一个；迁移不会替用户选择，也不编造执行历史。

任务定义拥有可编辑提示词和明确执行选项。每次接受请求都保存有效输入、Workspace、对话、交接和声明的发起来源快照。读取 version-1 任务时，通过形成明确提示词保留标题加描述的输入。已发布 Session 日志代次保持不变。

**已被取代的提示词默认规则：**空提示词只使用标题；描述仍是计划文本。[默认运行提示词](2026-09-10-taskboard-default-run-prompt.zh.md)拥有当前回退规则。

宿主在创建对话或提交输入前，持久保存 pending 执行和保留标识。它在发送输入前保存 provider 恢复证据，并将接受确认与完成分别记录。终态观察结果保持可用，直到 Taskboard 结算提交；随后才可释放 provider 连接。进程中断绝不授权自动重发提示词。

请求回执使用调用方拥有的标识，其保留独立于可见执行历史。重放检查先于可变默认值解析或新标识分配。同一 key 不能指向不同意图；回执过期后，旧请求仍须通过修订或计划时点检查。

一个配置明确的宿主通过内核持有的文件锁拥有执行权。进程死亡会释放所有权；时间流逝绝不能证明仍存活或暂停的所有者已停止。宿主取得锁后重新加载缓存的任务状态。已绑定的修改操作验证所有权，关闭时先拒绝新写入，再等待已接受的写入结束并释放锁。这既排除同时调度，也排除陈旧缓存写入。共享任务数据必须使用共享锁位置。

手动运行与 cron 使用相同的准入和 provider 操作。Cron 保存明确的 IANA 时区和五个数字字段。启动、时钟倒退恢复和较长间隔会跳过错过的执行时点。忙碌任务和对话跳过时点，而非排队补执行。恢复和复制后调度保持禁用。

DSH 输入使用共享 Session Controller 和精确 inbox/turn 证据。未固定设置保留关联 Session 的选择；任务专用模型选择不重写新 Session 的默认值。Copilot 使用受支持的 SDK 执行接口、有界 Agency 发现和精确对话标识。权限设置必须在输入前成功；无人值守默认为只读，提高任务权限需要明确保存的确认。

冻结交接文本是普通用户输入，不是 system 指令，也不授予权限。来源标识记录声明的出处，而非认证人员身份。权限或交接更改使相应确认失效。计划信息编辑不会重写尚未结束执行的不可变输入。

**已被取代的状态策略：** 执行结果与任务状态保持独立。智能体完成不会将卡片移到 In Review 或 Done。[列状态决策](2026-09-09-taskboard-execution-driven-columns.zh.md) 负责当前流程。关联、导航、断开、归档、恢复和删除任务都不提交工作，也不擦除对话。Open 绝不重建缺失历史。

可选设置通过普通已记录的 DSH system prompt 说明 Taskboard 规则，并在存在工作或已启用计划时请求空闲睡眠保护。它们不安装 Taskboard 模型工具、不安排机器唤醒，也不保证明确睡眠或关机期间继续运行。

## Alternatives considered

**保留浏览器拥有的创建、关联、提示和监控步骤。** 已断开的浏览器不能拥有持久调度或完成状态。宿主负责这些操作，Client 仍是投影和命令调用方。

**将终端创建视为执行接受。** 终端交接只确认 broker 接受请求。无界面 SDK 执行提供 provider 回执和监控；拥有的执行释放对话后，仍可交互式打开该对话。

**保留两个关联，或每次运行都创建新对话。** 两个关联使调度含糊，而替换会丢失上下文。明确断开让更改成为有意识的选择，并保留历史导航。

**自动重试接受状态不确定的提交。** 外部接受和 Taskboard 持久性不共享事务。重复提交可能重复文件或网络效果，因此未知接受状态会明确显示，而非静默重试。

**按时间戳使所有权租约过期。** 暂停进程可能在租约到期后仍存活，并随后恢复写入。内核所有权跨暂停保持，并在死亡时释放，无需有竞态的目录删除。

**使用已有 Session 提醒调度器。** Session 本地提醒要求其 Agent 在线，不负责宿主范围的冷对话 cron 调度。Taskboard 调度因此共享持久任务准入。

**根据智能体成功推导 Done（已被取代的否决）。** 执行无法证明人工审查或任务要求已满足。[列状态决策](2026-09-09-taskboard-execution-driven-columns.zh.md) 接受该限制，并赋予 Done 执行成功的含义。

## Testing

必需回归覆盖包括修订和请求竞态、保留的双关联选项、单调执行状态、不可变交接输入、同对话重复运行、结算写入失败、不重发的冷恢复，以及取得所有权后使用新鲜持久快照。provider 测试区分精确输入接受与通用 idle 状态，并在结算前保留证据。

内核测试在私有目录中验证竞争和崩溃释放。原生电源测试替代实际睡眠抑制，并证明静止收尾。[组装 Taskboard 场景](../../../../snapshots/web/taskboard-start-work/) 覆盖重复执行以及已记录的可选公告和交接；[管理场景](../../../../apps/web/tests/taskboard-management.e2e.ts) 覆盖保留的 UI 流程。已安装 Copilot 的互操作性由独立[隔离 provider 测试](../../../../packages/api/taskboard-controller/tests/copilot-interop.e2e.ts) 覆盖。

## Consequences

任务定义、运行历史和对话所有权明确，并在重启后可见。代价是 provider 专属恢复的宿主生命周期，以及必需的单写入者配置。有界回执和证据不承诺外部效果恰好一次；不支持的 provider 操作会失败，而非削弱权限或猜测成功。

API controller 像 Session 和 Workspace controller 一样保留宿主服务 peer。SQLite 只允许明确声明的兼容逐记录版本前进；旧写入者必须关闭，已提交升级不启用降级支持。协作式多进程编辑仍需要 SQL 层条件写入和持久变更流。
