# dsh-dashboard

[English](README.md) | 中文

## 概述

此私有配置叠加层在 Taskboard 和 Settings 旁添加工作看板，提供个人工作与 Azure DevOps 只读来源及按来源独立的原生问答。个人关注事项支持可撤销的本地决策和明确确认的问答提议，外部记录保持不变。页面默认打开个人工作，不会选中普通 Chat。打开时复用未过期的缓存数据。个人关注事项通过针对性的邮箱证据生成具体后续行动；发送问题会向已配置的原生模型提供所选证据。

## 使用此包

使用当前 DSH 源码提供的 Web profile，其中需包含原生 Client 的 `ISessions.retain` / `SessionReference` API。profile 必须提供原生 Agent/Session 服务、Session JSONL 持久化、`workspaceRegistry` 和持久化 JSON domain 存储。请分别完成 Agency WorkIQ/ADO 连接器和已配置 DSH 模型的身份验证；能够访问连接器并不表示模型已获授权。

### 设置：安装并连接 profile 配置

在此分支的检出目录中，使用[可跨机器使用的 Web 功能设置](../README.zh.md)构建本地依赖并安装完整 Web profile。隔离测试时，设置独立于正常安装的 `DSH_HOME`：

```text
pnpm run setup:web
```

[清单](package.json) 声明的配置叠加层仅通过[补丁](cordis.patch.yml) 插入 `dsh-dashboard` 条目。DSH 的基础配置叠加层提供原生服务，默认使用持久化 JSON domain 存储。自定义 profile 必须保留这些服务和下述存储路由；安装不会提供凭据。

默认 JSON 后端已覆盖 `dashboard_chat` 和 `dashboard_attention`。如果自定义 profile 选择了其他默认后端，请将这些 domain 显式路由到 `json`，并保留所有其他 domain 路由。

profile 补丁替换整个 `config` 对象，不会逐字段深度合并。此示例假定默认存储后端为 `json`。请保留 profile 的实际后端和所有其他路由：

```yaml
- id: storage-domain
  config:
    backend: json
    routes:
      dashboard_chat: json
      dashboard_attention: json
```

Host 插件在创建 Dashboard Session 前通过原生预设注册表发布私有预设。此预设选择独立于普通 Chat 工具执行器的作用域原生工具执行器。模型只能看到当前步骤获准使用的关注事项提案工具；不需要单独的预设根目录或诊断配套插件。

### Host 配置参考

依据 [Host 校验定义](src/host/index.ts) 配置 `dsh-dashboard` 条目。覆盖配置时，必须重新列出所有要保留的现有字段。

| 设置 | 默认值 | 含义 |
|---|---|---|
| `referencePath` | 未设置 | 可选的带日期本地 HTML 简报，不是实时依据。 |
| `defaultAdoSource` | 未设置 | 初始 ADO 链接或路径及来源选择参数。 |
| `timeZone` | `America/Los_Angeles` | 用于日历显示和刷新安排的 IANA 时区。 |
| `refreshMinutes`, `refreshMinute`, `workdayStart`, `workdayEnd` | `60`, `55`, `6`, `18` | 本地时钟间隔、锚点分钟、开始小时及不包含的结束小时；开始时间必须早于结束时间。 |
| `maxCalendarPages`, `maxPersonalItems` | `5`, `35` | 日历页数上限，以及个人数据集合和分区的数量上限。 |
| `attention.lookbackDays`, `attention.maxItems`, `attention.maxMessages` | `7`, `5`, `50` | 近期证据窗口、行动列表数量上限和每个定向邮箱查询的邮件上限。 |
| `maxAdoItems`, `adoPageSize` | `5000`, `1000` | ADO 读取数量和每页数量上限。 |
| `staleDays`, `blockedTags` | `7`, `['blocked']` | ADO 风险标记条件，并不证明工作停滞或延误。 |
| `adoAnalytics.ageBands` | `[7, 14, 30]` | 未完成工作项和当前状态龄期的递增天数阈值；未知日期单独保留。 |
| `adoAnalytics.historyDays`, `adoAnalytics.maxHistoryDays` | `30`, `120` | 近期历史窗口和日历天数上限；窗口不得超过上限。 |
| `adoAnalytics.maxHistoryItems`, `adoAnalytics.maxRevisionsPerItem` | `200`, `1000` | 所选类型的当前工作项集合上限和每项修订数上限；集合超限时拒绝读取，而非抽样。 |
| `adoAnalytics.revisionPageSize`, `adoAnalytics.historyConcurrency` | `50`, `4` | 每页修订数（最多 200）和并发历史读取数。 |
| `adoAnalytics.historyTimeoutMs`, `adoAnalytics.maxHistoryRequests` | `120000`, `400` | 整体历史读取时限和共享请求预算；缺失项会明确列出。 |
| `cacheSeconds`, `cacheEntries` | `600`, `8` | 自动来源读取的新鲜度窗口（10 分钟）和 Host 缓存条目上限。 |
| `chatSnapshotEntries` | `16` | Host 保留的不可变快照数量上限。 |
| `chatSnapshotRetentionMinutes` | `240` | 快照回执有效期，不是历史记录保留期。 |
| `maxChatContextBytes` | `128000` | 捕获证据的 UTF-8 字节上限，包括实际发送时的包装内容。 |
| `maxChatQuestionChars` | `4000` | 问题长度上限；HTTP 请求另有 32 KiB 字节上限。 |
| `maxChatOutputTokens` | `8192` | 原生模型输出 token 上限。 |
| `chatLockDirectory` | `dshHomePath('locks', 'dashboard')` | 用于 Host 独占写入所有权的绝对目录。 |
| `chatWorkingDirectory` | `dshHomePath('dashboards', 'workspace')` | 写入原生 Session 头部的专用绝对工作目录。 |
| `workiq`, `ado` | `agency mcp workiq`, `agency mcp ado`; `timeoutMs: 60000` | 连接器的 `command`、`args` 和超时设置。 |

Host 在使用前创建专用工作目录，并通过 `realpath` 解析它。新 Session 头部记录该规范路径。已有历史记录要求此规范路径目标保持稳定：`cwd` 缺失或不匹配、预设不兼容，或父会话、origin、seed 谱系不符时，均拒绝重新打开。运行时不会重写或迁移现有头部，也不会为缺失的历史记录分配新身份来替代。

预设无法解析、存储或工作目录不可访问，或写入所有权冲突，都会使 Host 初始化失败。

### 浏览与提问

在全局侧边栏打开**工作看板**。**个人工作**展示日历、通信和带日期的简报卡片；**Azure DevOps**支持冲刺或保存的查询链接，以及带组织和项目选择参数的迭代或区域路径。来源和工作项链接仍可点击。返回工作看板或重新加载同一浏览器标签页时会立即显示缓存内容。自动读取会跳过未满 `cacheSeconds` 的快照；过期快照在后台刷新期间及失败后仍然可见。圆形的**立即刷新**按钮会跳过新鲜度检查，在加载期间旋转并禁止重复点击。新鲜度取决于原始来源时间戳，重新打开不会延长有效期。标签页会在会话存储中保留最近的个人工作和 ADO 快照，不保存聊天或待完成操作；关闭标签页会清除显示缓存。存储失败时仍可复用内存数据。Host 重启后，如证据回执过期或不可用，需要先刷新再提问或调整。

紧凑标题栏、独立标签行、卡片和可折叠问答侧栏沿用应用现有主题。工作看板限定范围的颜色和内嵌 Inter 字体不会替换 Chat、Taskboard、Settings 或共享侧边栏的样式。不需要字体或图表 CDN。

个人工作的每个统计卡片都带有说明。“当前需要关注”采用近期邮件定向搜索（包括已读和已移动邮件），不再使用保存 HTML 中的旧关注事项。它仅纳入明确的个人事件分配或提及、直接客户请求、发布阻塞及本人 ECS 变更验证。每行提供具体下一步、个人关联依据、原文片段和带日期的原始邮件链接。重复事件及发布通知合并，已加载的较新回复和关闭信息会抑制旧请求，优先级建议不会变成虚构的截止时间或实时状态结论。查询有数量上限，可能遗漏回复或义务；行动前请核对来源。当前关注事项为空或不可用时都不会恢复旧保存任务。其他保存分区仍保留引用日期，日历解读与未知总数的含义不变。

**全部**、**已逾期**和**本周末**只筛选关注事项行。图表计数和统计卡片描述完整来源快照，其他分区保持不变。引用内容的分类依据保存简报的日期，而非今天的任务状态。未分类行保留在“全部”中。分类不可用时，页面明确展示“全部”，问题上下文和导出使用相同的显示选择。

### 调整个人关注事项

在关注事项旁使用**隐藏**、**标记已处理**或**稍后提醒**。这些决策只从个人关注视图排除项目，不会删除来源记录。标记已处理记录的是个人决策，不会验证完成情况或关闭工作项。关注事项摘要分别列出已加载项中可见、隐藏、已处理和稍后提醒的数量，以及原始来源总数；未知来源总数保持未知。

**审阅本地决定**展示被排除的项目，以及项目已不在当前简报中的决策。**恢复关注**移除排除状态。**撤销**恢复上一个决策，包括原有的稍后提醒截止时间，而不是一律显示项目。只有项目最新的可撤销操作才支持撤销；后续变更会使较早的撤销请求被拒绝。缺席项目只支持恢复。

稍后提醒要求在显示的看板时区内选择未来的某一分钟。不存在或重复的本地时钟分钟要求改选其他时间。到期仅重新计算本地视图，不读取来源或调用模型。刷新、简报重排和 Host 重启都保留已保存决策。身份由来源类型、规范安全链接和区分大小写的规范标题组成；链接或标题变化要求重新决策，不进行模糊匹配。详细内容或严重程度变化会使项目重新出现以供复核；身份有歧义的项目保持可见且不能调整。

可要求个人问答为一个明确项目提出调整建议。确认卡展示项目、操作、适用的截止时间和当前状态。**应用本地更改**持久化该确切提议；**取消**拒绝提议而不修改项目。模型每个问题最多暂存一项提议，不会应用变更。捕获的已排除项目支持恢复提议；缺席决策请通过复核控件处理。过期或失效提议要求重新提问，不会自动基于新证据重试。

确认结果不确定时，**重试已捕获操作**保留原始操作和请求 ID。**重新加载本地调整**刷新显示，但不会消除不确定性或允许另一项写入或提问。确认变更会同时更新显示快照和回执；后续问题和导出使用有效的关注事项选择，较早问题保留原始证据。本地控件和确认操作不会调用模型。

### ADO 交付分析

选择一种工作项类型，查看完成情况、剩余工作、风险标记、龄期、区域和当前归属。仅 `Completed` 表示完成；`Resolved` 仍未完成。`Unknown` 和 `Removed` 保持可见，但不计入进度、人员、风险或估算总数。来源不完整时，仅显示已加载项的计数。估算字段分开保留，不隐含小时单位。

收尾路径按以下顺序将每个符合统计条件的未完成项归入一个组：受阻、未分配、逾期、已解决、长期未更新、继续工作。风险条形图允许重叠，并单独显示去重后的工作项并集。前置项分组描述当前观察到的未完成、不可用或未发现未完成前置项的情况；存在关联并不能证明工作实际受阻。

龄期分段以真实的 CreatedDate 和 StateChangeDate 为依据，计算到快照时间。缺失或未来日期保持未知；ChangedDate 不会替代状态龄期。区域图和当前负责人图保留所有状态类别。负责人行按字母顺序展示符合统计条件的已完成和未完成计数，不代表作者、生产力、绩效或产能。

**加载当前工作项集合的历史**显式读取当前已加载且属于所选类型的工作项修订，并以各项捕获的修订版本为界。当前统计卡片不等待历史读取。历史视图展示这一当前工作项集合的完成项数量、状态类别数量，以及按日去重的完成和重新打开事件。一个工作项可在同一天完成并重新打开；每种事件各计一次。

不含迭代的来源使用配置的近期历史窗口。冲刺来源要求有效的开始和结束日历日期；范围缺失、无效、顺序颠倒或尚未开始时，历史不可用，不会改用近期日期。范围采用配置的时区，截止到快照时间，并遵守配置的天数上限。每张历史图均注明日期、日期来源、时区、读取时间和覆盖情况。缺失历史不视为零值观察；历史不可用时不绘制曲线。数量上限、提供方故障和整体时限可能导致历史部分可用或不可用，但不会移除当前统计卡片。

历史无法重建已从冲刺移除的工作项、历史团队区域配置或历史看板列。它不是完整冲刺的燃起图或燃尽图、看板累积流图，也不是产能预测。历史补充成功后会获得新的保留快照回执；先前问题继续使用原始证据。加载历史既不发起模型请求，也不改变来源的草稿或问答历史身份。

### 快照问题与选择范围

右侧**快照问答**面板为个人工作保留一份历史记录，并为每个规范化的 ADO 来源保留独立历史记录。ADO 身份包含组织、项目、可选团队、模式、解析后的查询/迭代/区域选择参数，以及是否包含子路径。链接别名和大小写会被规范化；筛选、排序、分页和所选详情不会产生另一份历史记录。切换来源或打开历史记录不会替换普通 Chat 的当前选择。

建议问题只填入草稿，不会提交。**新问题**将焦点移至输入框，不清空草稿或历史记录。模型标签为只读；面板不提供模型切换或斜杠命令。**复制回答**会报告剪贴板操作成功或失败。

发送前请查看显示的上下文和数据发送说明。Host 使用与当前显示内容一起保留的不可变快照，以及为该问题捕获的选择状态，包含捕获和读取时间、来源日期、过期状态及完整性警告。后续刷新不能为该问题替换成更新的数据。

ADO 的各类计数使用不同的选择范围：

| 显示内容 | 选择范围 |
|---|---|
| KPI、估算总数、交付、收尾、风险、龄期、区域、前置项和历史图表 | 类型、人员、状态、标签和文本；不采用指标、风险或图表下钻筛选。 |
| 实际状态图；无分析元数据时的人员图 | 返回结果中所选类型的全部工作项，不受其他筛选影响。 |
| 当前负责人归属 | 返回结果中所选类型的全部工作项，按字母顺序排列；不是生产力排名。 |
| 表格和问题的匹配行 | 所有生效筛选，覆盖全部页面。 |

刷新后，所选区域可能没有匹配行。即使配置的图表分段发生变化，已有龄期选择仍保留原来的数值区间。这两种情况都不会扩大表格选择范围，也不会缩小基础图表范围。

问题证据包含上述不同范围的总数和图表、全部匹配行、可见页和排序信息，以及所选工作项详情，不限于当前表格页。快照回执到期或被淘汰时，请求会被拒绝，必须显式刷新；上下文超限时，请求会被拒绝，需要缩小筛选范围或提高配置上限。这两类失败都不会静默替换数据或截断匹配行。

ADO 界面、导出和问答使用同一套报告计算。导出先捕获报告，再缩小匹配表格，因此筛选后的行不能替代完整类型的负责人计数或基础筛选范围的图表分母。问答仅接受 Host 保留的证据，不信任浏览器提交的导出报告。

已挂载 Client 中的草稿、错误和重试捕获内容按来源独立保存。发送被接受后，只清除其捕获的草稿版本；接受仅表示已入队，不表示回答完成。**重试原问题**保留原始请求 ID、问题、来源、快照和选择状态。Host 在检查快照到期或当前部署上限之前，先依据持久化回执核对已接受的请求。中断的请求接纳仍属不确定状态：请检查原生历史记录并核对已捕获的请求，不要盲目提交新问题。

**停止**只取消所选来源的原生 Session。切换来源或页面，以及释放原生读取租约，都不会取消已接纳的模型任务。来源读取的取消与模型取消相互独立。

看板历史记录和已提交证据保存在原生 Session JSONL 中；`dashboard_chat` JSON domain 保存来源映射和请求接纳回执。工作区归档使这些 Session 不出现在普通工作区列表中，但不是访问控制：原生 API 和本地日志仍可暴露它们。按来源隔离和专用工作目录不保证对这些读取方保密。已保存的按对话启用设置保持不变，也不用于页面可见性或历史记录。

## 理解实现

<details>
<summary>实现细节</summary>

[Host](src/host/index.ts) 按需创建并管理只读的 [MCP SDK 客户端和 Agency 子进程](src/host/mcp.ts)。它在 `/api/dsh-dashboard/` 下注册七个固定且经过身份验证的 POST 路由：`settings`、`snapshot`、`ado-history`、`chat-open`、`chat-send`、`attention-read` 和 `attention-write`。DSH Connection 负责身份验证和来源检查。Host 校验请求；Client 校验快照、提议和持久化确认结果。

`ado-history` 接受保留的 `snapshotId`、所选 `type` 和可选的 `force`。只读连接器允许列表包含 `wit_work_item/list_revisions`；调用方不能选择其他连接器操作。[历史加载器](src/host/ado-history.ts) 在快照修订版本界限内保留有数量上限的状态类别观察，而非无限制的修订正文。[共享报告](src/shared/ado-analytics.ts) 计算图表分组和下钻成员；[仅用于导出的投影](src/shared/export-types.ts) 保留报告，但不扩展问答所接受的证据。

[解读生成器](src/host/personal-insights.ts) 将解读与测量值分开。[关注事项选择](src/shared/personal-selection.ts) 向界面、导出和捕获证据提供相同的排序行，同时保留完整来源计数。本地时钟[刷新时刻](src/shared/schedule.ts) 不取决于读取完成时间。

[关注事项日志](src/host/attention-store.ts) 在 `dashboard_attention` 中原子记录每项决策及其幂等和撤销回执。其原生单文档 JSON 布局拒绝格式损坏或不兼容的存储，不会跳过记录。来源缓存与[有效视图发布](src/host/attention-views.ts) 分开；缓存命中和完成的来源读取都应用最新决策。完整操作去重在查找、校验、持久化和发布期间保留重复请求身份。提交后的发布失败保持结果不确定，不会被视为已证明的拒绝。

[聊天运行时](src/host/chat/index.ts) 负责原生 Agent 的创建和恢复、独占写入所有权，以及[持久化身份/回执 domain](src/host/chat/domain.ts)。原生 Session 日志和投影负责历史记录、流式输出、分页和取消；Client 通过保留的租约读取它们，而不是另建对话存储。Host 保留的[快照上下文](src/host/snapshot-context.ts) 在内存中受数量和时间限制，独立于来源缓存和持久化历史记录。

[分析预设策略](src/host/chat/preset-policy.ts) 仅接纳 Host 批准的问题。ADO 不提供工具。个人工作只获得绑定到 Agent 的提议能力，目标限于已接纳的不可变证据中的身份；继承、无关、嵌套和未批准的工具调用仍被拒绝。排队回执不是完成记录。

</details>

<a id="model-experience"></a>
## 模型体验

### 看板分析

#### 模型看到的内容

发送请求包含用户问题、捕获证据、按来源独立的原生历史，以及适当的固定[角色提示词](src/host/chat/capture.ts)。ADO 分析角色提示词的开头为：

```text
You answer questions about the supplied Dashboard snapshots.
```

两种角色提示词都将标题、描述、消息、链接和导入简报视为不可信证据，而非指令。Host 记录已接纳的问题和上下文消息，并在流式输出前持久化模型可见历史。它使用已配置的原生模型路由，不会替换。个人证据包含本地决策和受限的仅提议工具；记录的结果和确认卡都不表示来源任务已完成。模型不能应用调整、执行通用工具或通过连接器写入。

问答面板将用户消息和流式回答渲染为纯文本。最终回答使用带缓存的受限 Markdown：不解释原始 HTML，模型生成的链接保持为文本，图片只显示替代文本。不加载嵌入或远程资源。看板来源链接与问答文本分开，仍可点击。

#### Token 影响

打开、刷新和读取历史不会发起模型请求。定向邮箱查询只使用 WorkIQ fetch。每次发送会在来源的原生历史中增加问题和证据 token。证据字节上限不是整个对话的 token 上限；提供方上下文限制仍然适用。

#### KV 缓存影响

每个问题都会将捕获的证据追加到按来源独立的历史记录中。缓存复用取决于已配置提供方和保留的请求前缀；此包不保证缓存行为不变或必然命中缓存。

<a id="known-limitations-and-deferred-work"></a>
## 已知限制与待完善工作

这些限制适用于证据及其展示，也适用于基于这些证据的模型回答。

- 引用 HTML 提供带日期的纯文本和安全来源链接，不提供实时测量值。导入会移除活动标记、忽略没有安全链接的项目，并报告缺失日期或达到数量上限的分区。实时刷新不会重新验证导入内容的判断。
- 个人数据集合可能不完整。收件箱未读数不代表全部邮件；Teams 未读总数在证据不完整时保持未知。回复候选项来自启发式判断，可能已经回复。离岗计数表示通知记录，不代表不同人员；近期文件是有数量上限的 OneDrive 根目录直接子项，不是所有 Microsoft 365 文件。
- 调整属于此 Host/profile 的个人关注事项，不构成按认证用户隔离的数据分区或主题级规则。它们不会个性化 ADO，也不会挖掘普通 Chat。日志保留决策、目标标签与链接及回执；低频编辑会重写整个文档。复核和来源侧验证仍由用户负责。
- ADO 历史仅覆盖当前已加载的所选类型工作项集合，不代表完整的历史冲刺成员。当前状态类别不能重建历史流程或看板配置。部分结果仅描述已返回记录；较早的修改日期不能证明工作停滞。
- ADO 接受支持的 Azure Boards 链接或显式选择参数，不支持任意链接读取或用户提供的 WIQL。不支持团队范围的区域读取。团队冲刺要求一个精确迭代且不包含子路径；项目范围的迭代/区域路径可包含子路径。
- 定时刷新只在所选工作看板页面可见时运行。默认在配置时区的工作日每小时 :55 执行，从 06:55 至 17:55。自定义间隔以 `workdayStart:refreshMinute` 为锚点，并在 `workdayEnd` 前结束；错过或不存在的本地时钟时刻不会补执行。打开或返回视图时仅刷新过期或缺失的快照，也可在该时段之外读取。手动刷新始终跳过有效期检查。隐藏页面或浏览器会暂停来源读取和计时器，不会暂停已接纳的模型任务。没有调度器服务或邮件发送功能。
- 离线 HTML 的界面仅提供英文，包含看板数据而非问答历史。个人工作导出保留完整来源的关注事项计数和解读，仅筛选关注事项行。ADO 导出保留界面报告的各类统计范围、所有图表数据表、来源信息及显式加载的历史；匹配行对全部页面应用所有所选筛选。ADO 文件不含脚本，并支持仅通过 CSS 切换深色模式。文件无需 JavaScript 即可显示最终值，加载时不请求外部资源或刷新数据；点击来源链接会打开外部来源。

内嵌 Inter 字体使用 SIL Open Font License；构建将其许可声明包含在 `lib\licenses\inter-OFL.txt` 中。
